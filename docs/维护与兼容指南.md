# claude-hub 维护与兼容指南

桌面 `/Users/admin/Desktop/claude-hub` 是日常修改的主工作目录。这里同时包含
`claude1` 启动器和 `claude-hub` 网关，二者共用安装器、协议桥、测试和 Git
历史，不需要再去 Codex 的临时工作目录找源码。

## Provider 模型编辑的同步边界

Provider 菜单按 `→` 进入的模型页直接以 CC Switch SQLite
`providers.settings_config` 为权威数据源，只列出 `env` 中实际存在且受支持
的模型键。保存流程必须始终保持以下边界：

- 只修改当前选中的模型键，不重建 Provider，不改 `is_current`、Token、地址、
  `meta` 或未知 JSON 字段；
- 写入前用 SQLite online backup 保存到
  `~/.cc-switch/backups/claude1-model-editor/`，目录 `0700`、文件 `0600`；
- `BEGIN IMMEDIATE` 后重新读取原始 `settings_config`；与进入模型页时的快照
  不一致就停止并提示重新加载；
- 非当前 Provider 只更新数据库；当前 Provider 在普通模式下同步同一个 live
  模型键，在代理接管模式下同步 `proxy_live_backup`，不触碰代理占位 live；
- `~/.cc-switch/claude-hub.json` 与 Hub 模型列表不属于这条写入链路；
- 界面只显示模型字段，错误信息不得输出原始 JSON、Provider 凭证或完整地址。

对应回归测试集中在
`tests/test_launcher.py::ProviderModelEditorTests`。测试只能使用临时 SQLite、
占位 Provider 和 fake live 配置，不得复制真实 CC Switch 数据库。

## 第三方 Provider capability 与隔离合同

`claude1_provider.py` 是普通直连、OpenAI 临时 bridge 和固定 Hub 的唯一
capability schema。新增 Provider 特判时，先判断能否表达为 profile 字段；
不要在启动器、Hub handler 或协议转换器中按真实 Provider 名散落分支。

解析优先级为：当前 Provider/Hub 渠道的用户覆盖、Provider settings、
Provider metadata、safe default。每个字段单独记录 source 和 verification，
不得把一次探测结果推广到其他 Provider。默认值必须是 unknown、unverified、
unsupported、estimated 或 filtered 之一，不能用 Claude Code 的模型名猜测
第三方能力。

安全验收至少覆盖：

- custom base URL 缺少显式 Provider credential 时，在启动 Claude 或访问网络
  前失败；
- 临时 settings 和子进程环境不含 Claude.ai OAuth 状态；
- `resume`、`compact`、`subagent`、`background` 类请求只到当前 fake
  upstream，并始终使用当前 Provider credential；
- Tool Search、thinking、prompt cache、beta、count_tokens 和 `[1m]` 按当前
  profile 独立决定；
- bridge 只在 terminal event 发布稳定 usage，并保留可获得的 cache-read
  usage、stop reason、tool call 和 encrypted reasoning；
- doctor、运行日志和错误不输出 Token、完整上游 URL、Provider 名或私有模型
  ID。

Claude.ai OAuth、Remote Control、Fast Mode 和 Claude.ai connectors 是
Claude Code 官方控制面能力，不属于普通第三方 Messages API capability；
维护时不得用请求转换或伪造字段模拟这些产品能力。

模型页的标签列必须按终端显示宽度而不是 Python 字符数对齐，中文“主模型”
和英文角色名的模型值应处于同一列。角色色沿用现有调色板：主模型、Opus、
Fable、Sonnet、Haiku、Reasoning 分别使用 orange、violet、pink、teal、
lime、gold；低色终端使用对应基础色回退。INSERT 使用独立的可横向滚动
输入行，不把长模型名的光标钉在被截断的列表行上。

## 第一次在本机启用防泄漏门禁

```bash
cd /Users/admin/Desktop/claude-hub
./scripts/install-git-guards.sh
```

脚本只修改当前仓库的 `core.hooksPath`，会启用：

- `pre-commit`：扫描暂存区；
- `pre-push`：扫描即将进入远端的每个新提交，包括中间提交；
- GitHub Actions：在无本机私密数据的环境中扫描检出的仓库内容。

本机扫描会只读加载环境变量、`~/.cc-switch/cc-switch.db` 和
`~/.cc-switch/claude-hub.json`，把真实凭证、渠道名、别名和上游地址作为
私密指纹。报告只显示类别、文件、行号和短哈希，不显示秘密值。

手动检查命令：

```bash
python3 scripts/secret_guard.py --working-tree
python3 scripts/secret_guard.py --staged
python3 scripts/secret_guard.py --all-history
```

`--all-history` 用于人工审计；旧提交中的公开测试夹具可能被识别为通用秘密模式，
需要结合提交年代人工确认。日常自动门禁只检查当前内容和本次推送新增的提交，
不会因为远端早已存在的公开测试文本永久阻塞。

只有确认某一行是公开示例且属于误报时，才在该行加入
`secret-guard: allow`。不要为真实凭证、真实渠道或真实上游地址加豁免。

## 绝不进入仓库的内容

- `.env`、`.env.local` 等环境文件；
- `cc-switch.db`、`~/.cc-switch/` 的任何副本；
- `claude-hub.json`、`claude-hub-token`；
- API Key、OAuth Token、Bearer Token、私钥；
- 包含真实渠道名称、上游地址或备注的本机配置。
- `docs/design-references/local-private-*` 原始截图（可能把渠道名画进像素）。

示例配置只能使用明显的占位符。项目的 `.gitignore` 和 secret guard 会共同
拦截常见失误，但仍应在 `git diff --cached` 中人工确认提交范围。

## 修改后的固定验证顺序

```bash
cd /Users/admin/Desktop/claude-hub
python3 -m py_compile \
  claude-provider-once.py claude-hub.py claude1_protocol.py \
  claude1-turn-guard.py \
  scripts/secret_guard.py
python3 -m unittest discover -s tests -p "test_*.py" -v
./tests/test_shell_integration.zsh
./tests/test_install.zsh
python3 scripts/secret_guard.py --working-tree
git diff --check
```

需要把当前版本安装到本机时再执行：

```bash
./install.sh
source ~/.zshrc
claude1 doctor
```

`doctor` 是只读检查，不连接 provider。真实渠道联调应在上述离线测试全部通过
后进行，日志和错误信息中不得加入 token、完整上游 URL 或真实配置内容。

## 提交与同步

```bash
git status -sb
git diff --cached
git commit -m "简短说明"
git push
```

Git hook 会在提交和推送时自动检测。不要使用 `--no-verify`；如果被拦截，按
报告中的文件和行号删除敏感内容，再重新暂存和检查。
