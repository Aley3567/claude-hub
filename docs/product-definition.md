# 产品定义：claude1 / claude-hub

> 2026-08-16。本文由一轮产品定义讨论 + 74 题角色拷问整理而成，是重构（见 [claude1-refactor-design.md](claude1-refactor-design.md)）的产品侧依据。
> 全文学风约定：答案分【现状】（今天就能做到）、【部分】（有雏形）、【待建】（承诺而非现货）三档，不把待建写成现状。

## 定位（一句话）

**cc-switch 管渠道和凭证，本工具管它架构上做不到的多模型同时在线。**

cc-switch 是单 current provider 切换器，failover 是容灾不是路由；本工具把便宜/均衡/旗舰/长上下文四个模型槽位同时绑定不同渠道，会话内 `/model` 按任务换模型。是共生层，不是替代品。

## 现在能做到 / 这就是我们要建的

**现在能做到：**
- 多渠道启动 + 会话内 `/model` 切换；模型槽位路由（手工分配）
- 渠道与凭证只读自 CC Switch DB（schema 13–16），零迁移、互不打架
- 每会话临时配置，不污染全局 settings；卸载无残留
- Anthropic ↔ OpenAI Chat / Responses 协议桥；tool 因果校验
- 账号池（单渠道多账号 401/403/429 自动换号）；usage 记账（含 account/exact 字段）+ `usage` 命令统计图表
- 错误日志不含对话内容；网关只听本机回环
- macOS / Linux

**这就是我们要建的：**
- 观测出口：降级记录进持久 journal、可统计（宽容化的前置条件）
- 协议层宽容化 + 错误的"人话翻译 + 建议动作"层
- 韧性：错误分类重试、首字节/静默超时分级、常驻 hub 熔断器、能力画像驱动的 failover；并发压测数据
- 真实流量语料 → golden fixtures；preset/方言画像数据层
- 网页管理台（headless 核心 + HTTP 接口先行）；模型自动识别分槽
- 成本护栏：花费预估、高价渠道确认、预算熔断、阈值提醒
- Windows 适配、安装/迁移向导、渠道白名单（合规场景）

## 核心问答（精编）

**Q：这个能给用户带来什么？使用方便么？**
用简单的方式启动，帮助在 Claude Code、Codex、Pi 提供多渠道模型同时使用；可以兼容成本、增强性能、利用各个渠道模型不同的特性和优点，提供更加舒适的使用体验。

**Q：它是什么？**
一个多渠道模型的启动器 + 本地网关。在一个地方配好各家渠道，打开 Claude Code 就能用，会话里随时换模型，不改配置、不重启。

**Q：和 cc-switch 有什么区别？**
cc-switch 是单渠道切换器（同一时刻一个当前渠道）；我们是多模型同时在线，一个会话里按任务换模型。cc-switch 做不到的正是这件事。

**Q：多模型同时在线的实际体验？**
粗活走便宜快速的渠道，硬骨头走强模型，长上下文走大窗口渠道——按任务换，不按心情换。成本和质量同时最优。

**Q：渠道协议各不相同，怎么保证都能用？**
网关内置方言适配层：上游说什么方言就适配什么；行为怪异也容错放行。能原生直连的直连，必须转换的才转换。

**Q：出问题时能看到真正的原因吗？**
能。上游报什么错就看到什么错（语义保留、形状合规），失败绝不伪装成成功；成功但有降级的回合也留痕可查。

**Q：会改乱我的 Claude Code 配置吗？**
不会。每次启动用独立临时配置，会话结束即清理；全局 settings 一个字节不动；凭证只从 CC Switch 数据库只读使用。

**Q：怎么确保兼容？Windows/Linux/macOS/手机？**
核心用 Python 标准库 + 本机回环网关，架构上不碰平台专有 API。【现状】macOS/Linux；【待建】Windows；手机不单独做 App，走 SSH/浏览器。

**Q：乱七八糟的格式怎么在同一线程用？影响缓存么？**
线程永远只见 Anthropic 协议，方言由网关翻译。缓存说实话：同渠道内照常命中（网关做保洁，剥掉破坏缓存命中的杂讯头）；跨渠道切换那一次新渠道要重读上下文（冷启动），之后自建缓存。设计鼓励槽位固定渠道，命中率最高。

**Q：能自动识别模型吗？我很懒，要开箱即用。**
目标：装好敲 `claude1` 回车就进会话。渠道从 CC Switch 直接读（【现状】）；模型自动拉取 + 按便宜/均衡/旗舰/长上下文自动分槽（【待建】）；方言自动挂适配档案（【待建】）。网关自身开销毫秒级。

**Q：我是新手，能有 cc-switch 那种页面吗？**
能。网关本身是本地 HTTP 服务，界面只是遥控器：网页管理台在浏览器里加渠道、拖槽位、看用量查错误，手机浏览器同样可用。设计约束：核心永远 headless，TUI/网页/桌面壳都只是客户端。【待建】

**Q：我有 cc-switch 的配置，能直接拿来用吗？**
能，今天就能。渠道、凭证、模型配置直接读 CC Switch 数据库，零迁移；只读不写、不复制 key，两边同时用互不打架。注意：schema 适配目前限 13–16 版，CC Switch 升级 schema 是长期维护义务。

**Q：key 和聊天内容安全吗？**
钥匙不挪窝，内容不留痕。key 只存在 CC Switch 数据库，现取现读；日志只有元信息（时间、渠道、错误类型），没有对话本身；网关只听回环；无遥测无上报。

**Q：渠道挂了/限速了怎么办？**
同渠道多账号自动换号【现状】；渠道级主备切换【待建】，且切换前要判断备胎能力，接不住就明说，绝不装没事。

**Q：花了多少、哪个渠道在省/在烧？**
每回合按渠道和模型记账，`usage` 一条命令看统计【现状】；网页图表【待建】。看得见的账，才调得动的成本。

**Q：隔一层网关会变慢吗？**
本机回环，开销毫秒级；真正决定快慢的是渠道本身，网关把每个渠道的耗时如实记账。（高并发压测未做，单人日常无虞。）

**Q：第三方渠道会影响我的官方账号吗？**
渠道都是你自己的账号和 key，工具只做按配置转发，不碰订阅关系；发去哪家的请求只带哪家的 key。

**Q：不想用了好卸吗？**
删掉就完事。不改全局配置、不驻留后台、临时配置结束即销毁；CC Switch 配置从未被碰过。

## 附录：74 题拷问录

由三种人设（高频重度 / 中频普通 / 低频新手）+ 两派 cc-switch 死忠（实用派 / 技术派）密集拷问产生。每条：问题要点 + 应答结论 + 档位。

### 高频重度用户（15 题）

1. 多会话挤同渠道，账号池会不会互相挤进冷却？【部分】池状态在 SQLite 共享、有游标冷却；并发公平性没设计过也没压测过。
2. 200K 缓存命中率怎么保证？账单爆炸赔吗？【部分】原生渠道 cache_control 透传；跨协议转换会丢（已知降级）。不赔，但缓存命中记账可查。
3. tool_use id 不一致会不会已帮我调了真实工具？【现状】不会。tool_result 因果校验 fail-closed，对不上就拒。
4. 故障切到 GLM 但它不支持我的 tools 怎么办？【待建】能力画像缺失；failover 目前只认错误码。原则：备胎接不住就明确报错，不静默阉割。
5. usage 精确到每次请求还是估算？对账差 10%？【部分】响应 usage 取上游真实值带 exact 标志；count_tokens 是估算带标注。未与上游账单做大样本核对。
6. 跨机器配置/状态同步？【待建】不做。配置在 `~/.cc-switch/` 可自行同步，不承诺。
7. 自动分槽判断错了谁负责？【待建】功能未建；原则：自动分槽只是默认值，一秒钟可改，代价可逆。
8. 五渠道全被风控还有兜底吗？【部分】无无限兜底；last-error-wins 会点名最后一个目标的真实原因。
9. 未知字段里的 cost/cache 信息丢了还是乱记？【现状】usage 只从认识的口径提取并带 provenance，不认识绝不乱记。
10. 3 小时会话断流能断点续吗？【待建】不能。断流如实报错；重发靠提示缓存降成本。
11. 30 秒没响应，怎么区分网络/上游/网关 hang？【部分】journal 记 phase 和异常类型；超时单旋钮，无首字节/静默分级归因。
12. 单进程扛多会话，压测数据？【待建】没有，认账。
13. tool_result 敏感路径会落盘吗？【部分】journal 不写 payload；但上游错误 message 可能带路径，脱敏规则需从只防凭证扩展到路径。
14. 自动切换考虑实时成本吗？【部分】有定价数据（model-pricing.json）；按成本路由未建。现状是槽位固定渠道，不存在钉死贵渠道的自动切换。
15. 长会话手动切槽，上下文重喂还是继承？【现状】历史由客户端发给网关，切槽=新渠道收完整历史（一次冷启动）；system prompt 方言差异由适配层抹平。

### 中频普通开发者（15 题）

1. 家里 Windows 公司 macOS，配置同步吗？【待建】不同步、不承诺。"不污染全局"和"帮你同步"是两回事，只做前者。
2. 升级会不会搞丢配置？【部分】升级不碰 `~/.cc-switch/`；"升级前一键备份"该进文档和 doctor。
3. 公司代理 + 自签名证书？【待建】代理配置有（proxy_url/proxy_hosts）；自签名证书是记录在案的已知弱点（Python TLS 链路）。
4. 合规白名单渠道？【部分】有雏形（hidden、turn_guard）；"一键白名单 + 当前渠道显眼提示"待立项。
5. 一个月回来忘了命令怎么办？【部分】`claude1 list` 可看；内置引导没有，网页台就是答案。
6. HUB_DEGRADE_XXX 是啥意思？【待建】warning code 是机器用的，缺"人话翻译 + 建议动作"层——三类人设共同戳中，性价比最高待办。
7. 429 自动换号后怎么查走的哪个账号？【现状】usage 记录含 account / instance 字段。
8. 两台机器槽位静默漂移？【部分】风险真实（各自 DB）；doctor 应加配置指纹检查，对不上就明说。
9. 端口被 MDM 占了？【部分】临时桥用随机回环端口基本免疫；常驻 hub 端口可改，人话提示待补。
10. 30 行错误 JSON 直接喷给我？【部分】现状整形+脱敏；缺人话摘要层。
11. 只有 Python 3.11 跑得动吗？【待建】版本下限与安装包形态未定义，packaging 待办。
12. 五六个窗口同时开，槽位互相影响吗？【部分】临时桥模式每会话独立；常驻 hub 共享。两种语义须在文档写死。
13. key 快没钱会提前说吗？【待建】多数上游无余额 API，只能失败后如实报错；可做用量趋势推算。
14. 一条命令查今天的简明账单？【现状】`usage` 子命令，按渠道/模型统计带图表。
15. CC Switch 改了表结构？【部分】schema 版本检测 fail-closed 明确报错（姿态正确）；欠"支持到 X 版"公开声明。

### 低频新手（14 题）

1. 安装要输密码吗？会搞坏电脑吗？设计上只动用户目录、不需要密码，安装前列出要动的文件清单。（install.sh 逐行审计待验证。）
2. 没装过 Claude Code 会卡死吗？【待建】是前置依赖；保姆式安装向导待建。
3. 有图标双击打开吗？【待建】网页台出来后做书签/快捷方式，体验等同。
4. 有保姆提示吗？贴错了会一直错吗？【待建】向导待建；原则：每步可重入，不累积错误。
5. 不懂槽位，能一个"便宜但别太慢"按钮吗？【部分】这正是自动分槽要给的默认体验；现状手工配。
6. 英文报错有翻译按钮吗？【待建】人话层，欠账。
7. 网络卡了刷一片红，该等还是重启？【待建】错误该直接告诉用户"等"或"重试"。
8. 误用最贵模型，确认前能告诉大概多少钱吗？【待建】高价渠道确认 + 成本预估。
9. 用量在哪看？钱花完会提醒吗？【部分】命令行能看；阈值提醒待建。
10. 能设"本次最多花 X 元"硬上限吗？【待建】预算熔断。与高频 14 题合并为"成本护栏"模块。
11. 手滑删了配置会连 Claude Code 一起坏吗？【现状】不会。配置独立，doctor 可体检修复。
12. 家人乱点会删掉配置吗？【待建】命令行天然免疫；网页台需"查看模式/操作确认"。
13. 换电脑配置能带走吗？【部分】拷走 `~/.cc-switch/` 那几个 json 即可；迁移指南没人写过。
14. 有"彻底不玩了"的红色按钮吗？【现状】实质上有：不驻留后台，常驻 hub 显式启动，停掉即彻底退出。

### cc-switch 死忠 · 实用派（15 题）

1. "50+ 预设 vs 手配？"前提错误：cc-switch 里配好的渠道直接读，零重配；但预设数据层（自动填端点/价格/上下文）认账待建。
2. "槽位给空气看？"半对：槽位机制现成能用，缺的只是初始自动分配。
3. "2026 年用终端玩具？"不辩解。短期答案：渠道管理继续用 cc-switch GUI，我们的网页台只做它不管的（槽位/用量/降级）。
4. failover 甩飞还是等死？现在是后者（单旋钮超时），韧性欠债在案。
5. "凭什么再信宽容解析？"现在没有凭据。信任三件套（宽容策略+降级可见+真实语料）是里程碑不是口号。
6. 自嗨测试？认。639 绿灯只证明我们和我们的想象一致。
7. "永远慢半拍的尾巴？"是尾巴，认；这是共生定位的设计选择。
8. 人话层？认，性价比最高待办。
9. 旗舰挂长上下文跑一晚谁拦？现在没人拦；成本护栏已立项。
10. Windows 同事活该？认账，承诺不是现货。
11. "离不开 cc-switch 还喊替代？"从没喊过替代。定位写死：cc-switch 管渠道凭证预设 GUI，我们做它架构做不到的多模型同时在线。**共生，不是替代。**
12. 错误翻译成本甩给用户？认。
13. "规划中"="意淫中"？公允。区别：有架构约束（headless 核心）和成文设计；但代码没写就是没写，网页台落地才销账。
14. 作者一个人业余时间？是。缓解：决策文档化、测试套件、站在 cc-switch 公开修复史肩膀上。不自称生产级。
15. /model 秒切保证不丢消息？机制有（格式抹平、tool 因果校验、冷启动已诚实说明）；保证强度=测试强度，绕回第 6 题。

### cc-switch 死忠 · 技术派（15 题）

1. SSEParser 有真实畸形语料验证吗？处理了 UTF-8 跨 chunk、CRLF/LF/CR 混合（有单测），但 fixture 全自造：逻辑在，证据等级低。
2. 乱序 tool_use 怎么处置？有按 index 归位的状态机；真实乱序 case 没有，补乱序测试在清单上。
3. 重复 id 下游会炸吗？tool_use id 重复直接拒；message id 重复的下游行为无自动化回归，认。
4. 怎么证明不是卧室重踩坑？证明不了，直到语料落地。辩护：逐行读过 transform.rs/streaming.rs 和八个版本修复史再动手，踩坑史是继承了的。
5. 600s 干等 10 分钟？澄清：sock_read 是读间隔不是总时长；但无分级，慢上游和挂死同一把尺，认。
6. 熔断器在哪？没有。临时桥形态下做不了，只能放常驻 hub。
7. 丢 cache_control/signature 叫能用还是有损？既然降级用户看不见，现状就是"有损且不可见"——不包装这个词。降级可见化第一优先级。
8. len//4 估算害我超支算谁的？估算带 `x-hub-estimated` 头不伪装精确；只用于展示，绝不做预算熔断依据（写进成本护栏设计约束）。
9. schema 17 追着发版？是，外挂读取器的宿命。防线是版本检测 fail-closed；适配 SLA 欠着。
10. 慢请求占住 event loop 四槽位一起卡？aiohttp 异步理论上不互卡；无 worker 隔离也无压测，"理论上"先挂着。
11. 巴士因子？认。不敢让人生产依赖，也不这么宣传。
12. 原样透传把 Claude Code 搞崩？戳中原则漏洞。修正："原样"以下游可解析为界——转译路径错误体必须整形为 Anthropic error shape，只有 native 路径字节级原样。（已写入重构设计 2.2。）
13. 降级不可见，事后排查靠什么？现在靠截图回忆，认。"先修观测出口再谈宽容化"的原因。
14. 各家改行为谁追 changelog？现状手改代码追；缓解：preset 数据层 + 读 cc-switch 更新作为方言情报。
15. 宽容边界靠心情？有成文三档定义（exact/degrade/reject，reject 只限安全因果，见 AGENTS.md）；但每字段归档的测试覆盖不全，认。

## 拷打收敛：结构性欠账清单

1. **人话层**（被戳最多次）：warning code、错误 JSON、超时归因，全部缺"说人话+建议动作"。性价比最高。
2. **成本护栏**：预估、高价确认、预算熔断、阈值提醒——从"记账"升级为"护栏"。
3. **能力画像**：failover 不认识备胎能力，会切出残缺结果——宽容化之后下一个正确性问题。
4. **并发与压测**：账号池公平性、单进程瓶颈，没有数据只有嘴硬。
5. **跨机器与合规**：同步的官方态度（不做就明说）、白名单、配置指纹漂移检查。
6. **新手闭环**：安装向导、人话报错、迁移指南——现状是"PPT 级别"。
7. **定位写死**：共生不是替代，放 README 和产品定义第一句。
8. **"可信"是工程里程碑**：宽容落地+降级可见+真实语料，不齐之前"兼容好"是口号。
9. **成熟度证据链**：压测、真实 case 回归、schema 适配声明、版本下限——没有就是没有。
10. **自我定位降级为诚实**：个人/小团队工具，写进 README。
